# Проверка сборки 1.0.4

Дата: 30 октября 2026. macOS 26.2, Apple Silicon, Swift 6.3.2.

## Сочетания из двух клавиш

В 1.0.4 из всех стандартных сочетаний убран Control: используется Option и
клавиша действия. Команды сгруппированы у левого Option: Q/W, A/S, Z/X/C/V.
Текущие настройки содержали пустой словарь переопределений,
поэтому новые значения применились без сброса параметров линзы. Release-сборка
завершилась успешно; новая подпись прошла проверку по требованию версии 1.0.2.
После обновления проверка через Launch Services вернула `preflight=true`.

## Разрешение после обновления

Причина несовпадения включённого переключателя и отрицательного статуса:
предыдущие версии использовали ad-hoc подпись с требованием `cdhash`. После
изменения бинарного файла старое разрешение macOS не соответствовало новому коду.

В 1.0.2 добавлен постоянный локальный сертификат в отдельной связке ключей.
Требование подписи привязано к идентификатору приложения и отпечатку сертификата,
без ослабления до одного bundle ID. На двух разных сборках проверено совпадение
требований и успешная проверка второй сборки по требованию первой.
Корневое доверие системы и разрешения других приложений не изменялись.

Новая проверка доступа получает настоящий кадр через ScreenCaptureKit.
Интеграционный тест с принудительным `preflight=false` подтвердил: доступный
поток не блокируется, успешный результат сохраняется после обновления статуса.
Регрессионные проверки исключения собственной линзы прошли повторно.

Предыдущие тесты живого потока запускались из терминала агента и не доказывали,
что разрешение есть у самостоятельно запущенного `.app`. Проверка 1.0.2 через
Launch Services до повторного согласия вернула `preflight=false`. Старая запись
разрешения сброшена адресно для `dev.local.FocusLens`. Пользователь подтвердил
работу приложения после выдачи доступа. При следующем обновлении до 1.0.4
разрешение сохранилось: самостоятельный запуск вернул `preflight=true`.

## Исправление рекурсивного захвата

В 1.0.0 тест живого захвата проверял наличие кадров, но не исключение собственных
окон. Пользователь обнаружил рекурсию после включения линзы.

Баг воспроизведён интеграционным тестом: перед показом панели запрос
`onScreenWindowsOnly: true` вернул `ownApplications=0`, а запрос с `false` — `1`.
Поток старой реализации захватил собственную цветную тестовую панель.

В 1.0.1 используется `onScreenWindowsOnly: false`, и запуск запрещён, если
собственное приложение не найдено для исключения. После исправления тот же тест
подтвердил: контрольный нефильтрованный захват видит панель, поток линзы её исключает.
Добавлен сценарий повторного старта при скрытых окнах и создания новой панели
уже после запуска потока.

## Базовые проверки

Проверено:

- Debug- и release-сборки в режиме Swift 6; без внешних зависимостей.
- 6 тестов Swift Testing. Один параметризованный тест охватывает 20 сочетаний
  формы и положения; каждое проверено на трёх виртуальных экранах во всех углах.
- Преобразование Retina 2×, отрицательное положение внешнего экрана,
  неподвижное закрепление при движении источника, центрирование указателя у края.
- Сохранение параметров в JSON и нормализация недопустимых значений.
- Нативная отрисовка окна настроек и всех четырёх линз на искусственном изображении.
- Правильная вертикальная ориентация кадрирования по четырём цветным квадрантам.
- У панелей установлены пропускание кликов и запрет перехвата клавиатурного фокуса.
- Живой поток ScreenCaptureKit: за двухсекундную проверку получено 70 кадров,
  размер 3456 × 2234 пикселя. Кадры не сохранялись; после остановки последний кадр освобождён.
- Проверена структура Info.plist, синтаксис shell-скриптов, локальная подпись `.app`.

Не проверялось автоматически: реальное переключение двух физических мониторов,
полноэкранные приложения и Spaces, срабатывание сочетаний во всех сторонних
приложениях, DRM-видео. Для них в README есть короткий ручной сценарий.

На установленном наборе Command Line Tools Swift Testing требует явных путей к
Testing.framework и lib_TestingInterop.dylib. Это учтено в `scripts/test.sh`;
полный Xcode для выполненных проверок не потребовался.
